# 功能与交互逻辑总览（giveaway）

> 面向 1.0 评审的功能清单：当前实现、交互路径、配置面、数据模型、多语言与测试覆盖，最后一节是 1.0 发布条件评估。
> 对应版本：**0.1.3**（Koishi 4.18+，`database` + `assets` 必需，`puppeteer` 可选）。

## 1. 插件定位与运行形态

| 项 | 内容 |
| --- | --- |
| 包名 / 指令根 | `koishi-plugin-giveaway` / `giveaway`（别名 `抽奖`） |
| 上游 | 派生自 [Roll-Bot-Project/roll-bot](https://github.com/Roll-Bot-Project/roll-bot)，分叉后大规模重做，本仓库独立维护 |
| 服务依赖 | `required: ['database', 'assets']`，`optional: ['puppeteer']`（缺 puppeteer 时全部图片自动回退为文字） |
| 平台 | OneBot（QQ）为主要目标：参与条件取数、`@` 中奖者、头像 qlogo 都基于 OneBot；其它平台可用基础功能，条件检查会自动跳过 |
| 语言 | zh-CN / en-US / de-DE 三语（消息、指令表、控制台配置描述、图片卡片标签） |
| 数据 | 8 张自有表 + Koishi 自带 `binding`（见 §8） |

## 3. 交互流程

### 3.1 创建抽奖（`创建抽奖`）

1. 机器人发一份**纯文本模板**（含当前控制台的参与条件）：

   ```
   奖品：
   开奖时间：
   加入口令：
   标题：
   描述：
   参与条件：等级≥40 活跃≥1 标识=群聊炽焰,龙王
   说明一：… 说明二：…
   ```
2. 用户复制填写后**一次回复**即完成；解析**按标签**取值（中/英/德标签、全角冒号、附带说明行都可）：
   - 奖品必填（`名称*数量`，逗号 / 空格 / 顿号分隔，旧 `|` 兼容）
   - 开奖时间支持 `月-日-时-分` 与 `年-月-日-时-分`；留空 = 不自动开奖；非法值明确报错
   - 标题 / 描述留空走默认；口令留空 = 不用口令（不参与关键词匹配）
   - **参与条件行三种语义**：不改（沿用控制台）/ 删空（本抽奖不限制）/ 改写（只覆盖写了的项）
3. 取消路径：回复 `q` / `quit` / `cancel` / `取消` / `abbrechen`、超时不回、缺少奖品行、时间或条件格式非法 → 一律取消本次创建
4. 位置参数写法（`抽奖 add 显卡*1 09-15-20-00 参加`）跳过模板步骤；`-t/-d/-r` 仍可用
5. 成功：`render.create` 开启时**只发图片卡片**（编号 / 标题 / 开奖时间 / 描述 / 口令 / 奖品 / 参与条件），否则发文字提示（含口令）

### 3.2 参与 / 退出

- **口令参与**：群里发送的消息与口令完全一致即参与（空口令不参与匹配）
- **指令参与**：`加入抽奖 <编号>` / `退出抽奖 <编号>`
- 参与前逐项校验参与条件，不通过时回复**具体原因**（当前等级 / 上次发言距今 / 缺少哪个标识 / 数据不可用）
- 重复加入、未加入退出、抽奖不存在都有独立回执；抽奖已开奖不可加入

### 3.3 查询

- `抽奖列表 [平台] [频道id]`：本频道进行中 / 已结束（可跨频道）
- `抽奖详情 <编号>`：开奖时间、描述、口令、**当前生效的参与条件**、奖品、参与名单；已开奖追加中奖名单
- `抽奖成员 <编号>`：参与名单（头像 + 昵称 + QQ 号，人数上限 `render.memberLimit`，超出提示「…… 等共 X 人」）

### 3.4 开奖

- **定时**：创建时填了开奖时间的抽奖到点自动开奖
- **手动**：`开奖 [编号]`（不填编号会列出自己创建的未开奖抽奖）
- 开奖结果广播到抽奖所在的**全部频道**：一条带真实 `@中奖者` 的文字行 + 结果图片（`render.result`）
- 开奖后按 `cacheHours`（默认 72h）保留记录，到期自动清理参与名单 / 奖品 / 频道关联

### 3.5 提醒（`remind.rules`）

- 控制台配置一张**按剩余时长分档的规则表**：每行 = 时长上限（`30m`/`1h`/`5h`/`1d`/`7d`，`0` 或留空 = 不限）+ 提醒位置（剩余时长的百分比，可写多个 `20,10`）
- 一个抽奖**只命中一行**（上限最小且 ≥ 自身时长）→ **默认每场只提醒一次**；提醒时刻 = 开奖时间 − 剩余时长 × 百分比
- 默认 `1h→20%` / `5h→15%` / `1d→10%` / `不限→10%`（1 小时场次 → 开奖前 12 分钟；7 天场次 → 开奖前约 16.8 小时）
- 到点在抽奖所在全部频道播报倒计时（按频道语言本地化）
- 生命周期：**开奖 / 删除 / 记录过期时自动取消**该抽奖的提醒任务；机器人重启时按新配置重建（以启动时刻为基准，已过去的提醒不补发）

## 5. 权限模型

- 只使用 **Koishi 原生 authority**（0 封禁 / 1 用户 / 3 管理员 / 4 超管），插件不再维护自己的管理员名单
- 抽奖**创建者**始终可以管理自己的抽奖；群主 / 群管按两个开关决定能否删除与手动开奖
- 管理类指令（`开奖` / `删除抽奖` / `时区` / `语言` / 诊断）按 `authorityManage` 判定
- 参与条件与权限无关：任何人都要过条件才能加入

## 6. 参与条件（可组合）

- 数据来源：`get_group_member_info`（`level`、`last_sent_time`）+ QQ 群荣誉接口（`performer_list` / `legend_list` / `talkative_list`，含 `day_count` / `day_count_max`）
- 荣誉取数走**自实现的新版网页接口**（`qun.qq.com/cgi-bin/qunapp/*` + `bkn` CSRF + Cookie 探测），因为 NapCat 的 `get_group_honor_info` 在 QQ 改版后失效
- 拒绝时说明具体原因；`onFetchError=放行`（默认）避免误伤
- **per-roll 覆盖**：详情/参与条件行里能文本表达的项（等级 / 活跃 / 连续 / 标识）可覆盖；文本表达不了的口径（`honorMode`、`dragonScope`）只在控制台配置、对全部抽奖动态生效；与全局等价的策略不落库

## 7. 图片渲染

- 五张卡片：创建结果 / 抽奖详情 / 参与名单 / 抽奖列表 / 开奖结果，共用一套 DOM + 三套主题 CSS（`default` / `anime` / `avemujica`）
- 尺寸：`body` 收缩到卡片（`display:inline-block`），**图片宽度 = 卡片宽度 + 内边距**，宽度由 `render.width` 控制（避免按浏览器视口截图导致的两侧大片背景与字体过小）
- 中奖者 / 参与者：头像优先取 OneBot 用户资料，取不到按 QQ 号拼 qlogo；昵称取不到退化为 QQ 号，头像失败显示首字
- 回退：未装 / 未启用 puppeteer，或渲染抛错 → 只打一条 `warn` 并回退文字，**不影响开奖、列表等业务逻辑**

## 8. 数据模型

| 表 | 用途 |
| --- | --- |
| `roll` | 抽奖主体（编号 / 标题 / 描述 / 口令 / 开奖时间 / 是否自动开奖 / 是否已开奖 / 中奖人可否重复） |
| `prize` / `roll_prize` | 奖品与「抽奖-奖品」关联 |
| `roll_creator` | 创建者（内部 user id） |
| `roll_member` | 参与名单（按加入顺序） |
| `roll_channel` | 抽奖与频道的关联（决定广播范围） |
| `user_prize` | 中奖记录（用户 × 奖品 × 数量） |
| `roll_policy` | per-roll 参与条件覆盖（无行 = 沿用控制台） |
| `binding`（Koishi 自带） | 内部 user id ↔ 平台号（QQ 号），头像 / 昵称 / `@` 都依赖它 |

## 9. 事件（前缀 `giveaway/`）

`roll-add`（参数 session、roll、奖品、可选 per-roll 条件）、`roll-end`、`roll-expired`、`roll-join`、`roll-quit`、`roll-key-update`（口令缓存刷新）、`remind-broadcast`（开奖提醒到点，参数 roll id）。

## 10. 多语言

- 三语文件：`src/locales/{zh-CN,en-US,de-DE}.yml`，key 集合、`{占位符}`、元素标签三语一致；en/de 无中文残留
- 覆盖范围：群消息、指令描述与选项、控制台配置项与下拉标签（含 `$inner` 按 union 下标对齐）、图片卡片标签、提醒倒计时、**管理员诊断输出**
- 用户**输入**解析同样多语言：创建模板标签、参与条件 token（等级/level/Stufe …）、取消词（`q`/`cancel`/`取消`/`abbrechen`）
- 例外（有意保留中文）：插件日志、`honorProvider` 返回的底层错误串（仅在诊断输出与日志中出现）、代码里的中文兜底描述（三语描述来自 locale 文件，代码值只作 `''` 兜底）
- 校验：`i18n-test` 用例（key 集合一致 / 占位符一致 / 标签一致 / en-de 无 CJK / 每条消息可渲染 / **代码引用的文案键都存在**）

## 12. 已知限制与风险

1. **荣誉接口依赖 QQ 网页接口**：接口或鉴权方式一变就可能取不到数据（有 `onFetchError` 放行兜底与诊断指令，但没有自动化探测告警）。
2. **平台覆盖**：参与条件、头像、`@` 都按 OneBot 设计；其它平台只有基础抽奖能力（文档已说明，但未做端到端验证）。
3. **图片依赖 puppeteer 与浏览器**：快照式 Chromium 在部分环境需要额外参数；渲染失败只回退文字（可接受）。
4. **没有 WebUI / 控制台面板**：全部交互在群聊与控制台配置里（原计划里的 console 面板未做）。
5. **上游遗留**：提醒引擎（node-schedule 封装）来自上游，目前只服务于控制台规则提醒；`crowdin.yml` 与远端 `l10n_master` 分支的翻译流程未纳入发布流程。
6. **压力/并发**：大群（数百人）名单与图片体积、并发开奖的竞态没有专门压测。

1.0 作为正式版本发布时按「全新开始」对待：不承诺与 0.1.x 的配置 / 数据结构兼容，用户按最新文档重新配置即可。

发布前建议顺手完成（非阻塞）：

1. 发版检查清单固化为流程：`npm ci → npm run build → npm test` 全绿 → 更新 CHANGELOG → 打 tag → 发 npm → 轮询插件市场收录。

3. 把「QQ 群荣誉接口依赖网页接口」的说明放在 README 显眼位置（当前在「参与条件」一节），方便使用者遇到取数失败时快速定位。
