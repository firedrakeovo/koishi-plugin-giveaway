# koishi-plugin-giveaway

[![npm](https://img.shields.io/npm/v/koishi-plugin-giveaway?style=flat-square)](https://www.npmjs.com/package/koishi-plugin-giveaway)
[![license](https://img.shields.io/badge/license-MIT-blue?style=flat-square)](https://github.com/firedrakeovo/koishi-plugin-giveaway/blob/master/LICENSE)

一个多功能的 Koishi 群抽奖插件：**复制模板即可创建抽奖**、支持参与门槛（群聊等级 / 活跃度 / QQ 群互动标识）、口令或指令两种参与方式、定时自动开奖与开奖前提醒，权限沿用 Koishi 原生等级，内置简体中文 / English / Deutsch 三语与多时区。

> A versatile giveaway plugin for Koishi: **create a giveaway by filling in a text template**, member join conditions (group level / recent activity / QQ group honors), keyword or command based joining, scheduled auto-draw and reminders, Koishi-native permissions, i18n (zh-CN / en-US / de-DE) and multi-timezone support.

> 本项目派生自 [Roll-Bot-Project/roll-bot](https://github.com/Roll-Bot-Project/roll-bot)（MIT，已保留上游版权声明）。分叉之后功能已大规模重做，本仓库作为**独立插件**维护与发布，问题请提到本仓库。

## 特性

**创建与参与**

- **复制模板创建**：`创建抽奖` 发一份文字表格模板（含当前控制台的参与条件），逐项填写后发回即可；留空即默认，解析按标签取值，群里随口一句不会被误当成奖品
- **每个抽奖可单独设置参与条件**：模板里的「参与条件」一行可沿用控制台配置、删空（该抽奖不限制）或改写（自定义门槛）
- **两种参与方式**：在群里发送抽奖的**加入口令**，或使用 `加入抽奖 <编号>`
- **抽奖详情显示当前生效的门槛**：参与者被拒之前就能看到条件

**抽奖流程**

- **定时自动开奖**：到点自动开奖，也可随时手动 `开奖`；开奖后按 `cacheHours` 自动清理记录
- **开奖消息 @ 中奖者**：中奖行是真正的 @ 元素（QQ 里会提醒到人），并保留 QQ 号便于留档
- **图片渲染（可选）**：安装并启用 `koishi-plugin-puppeteer` 后，`抽奖列表` 与开奖结果会用 HTML 模板渲染成图片；未安装 / 未启用 / 渲染失败时自动回退为文字消息，开奖消息仍保留带 @ 中奖者的文字行
- **开奖提醒**：定时开奖前按控制台配置的「开奖前 N」自动在群里提醒（可配多个时间点，如开奖前 1 小时 + 10 分钟）；无需在群里创建提醒器

**参与条件（可组合，任一不满足即拒绝并说明原因）**

- **群聊等级下限**（QQ 群聊等级 1~100）
- **最近 N 天内发过言**（最稳的条件，不依赖 QQ 网页接口）
- **最长连续发言天数**（可自定义门槛，如「连续 ≥ 14 天」）
- **QQ 群互动标识**：群聊之火（连续发言）、群聊炽焰（连续 30 天）、龙王（昨日活跃，可选「昨日活跃榜 / 仅当前龙王」两种口径）
- 荣誉数据由插件自己调 **QQ 新版网页接口**获取（NapCat 自带的 `get_group_honor_info` 因 QQ 荣誉页改版已失效），详见 [参与条件](#参与条件)

**其它**

- **权限沿用 Koishi 原生等级**：创建、管理他人抽奖分别配置最低等级；群主 / 群管理员可管理本群抽奖；创建者始终可管理自己的抽奖
- **多语言 / 多时区**：简体中文 / English / Deutsch 三套语言包翻译齐全，`语言` 指令可按用户或按频道切换；用户可自设时区
- **自带构建**：`npm run build`（esbuild + js-yaml，仅依赖 devDependencies）
- **管理员诊断指令**：`抽奖接口诊断` / `抽奖成员诊断` 一键体检数据来源

## 安装

```bash
npm i koishi-plugin-giveaway
```

或在 Koishi 控制台的「插件市场」搜索 `giveaway` 安装。

依赖的服务（**必需服务缺失时插件会静默不注册任何指令**，务必确认都已启用）：

| 服务 | 必填 | 说明 |
| --- | --- | --- |
| `database` | ✅ | 任意数据库插件（SQLite / MySQL / PostgreSQL / Memory 均可） |
| `assets` | ✅ | 资源存储，例如 `koishi-plugin-assets-local`；**它自身依赖 `server`**，因此 `server` 也必须启用 |
| `puppeteer` | 可选 | 由 [`koishi-plugin-puppeteer`](https://www.npmjs.com/package/koishi-plugin-puppeteer) 提供；装上并启用后，`抽奖列表` 与开奖结果自动改用图片渲染，没装也能正常使用（自动走文字消息） |

## 指令列表

所有指令都挂在根指令 `giveaway`（别名 `抽奖`）下。子指令可写全路径（`giveaway.detail`）或直接用别名（`抽奖详情`）；`giveaway.h` 这类短别名需连同 `giveaway` 一起输入。前缀由应用配置决定（本机可为空、`。` 或 `.`）。

| 指令 | 中文别名 | 参数 | 权限 |
| --- | --- | --- | --- |
| `giveaway` | `抽奖` | — | 任何人（输出指令一览） |
| `giveaway.add` | `创建抽奖` | `[奖品] [开奖时间] [口令]`<br>选项 `-t` 标题 / `-d` 描述 / `-r` 允许重复中奖 | ≥ `authorityCreate`（默认 1）或群主/群管理员 |
| `giveaway.list` | `抽奖列表`、`在抽啥` | `[平台] [频道id]` | 任何人 |
| `giveaway.detail` | `抽奖详情` | `<编号>` | 任何人 |
| `giveaway.join` | `加入抽奖` | `<编号>` | 任何人（需满足参与条件） |
| `giveaway.quit` | `退出抽奖` | `<编号>` | 任何人 |
| `giveaway.member` | `抽奖成员` | `<编号>` | 任何人 |
| `giveaway.end` | `开奖` | `[编号]` | ≥ `authorityManage`（默认 3）、创建者，或群主/群管理员（开关可关） |
| `giveaway.delete` | `删除抽奖` | `<编号>` | ≥ `authorityManage`（默认 3）、创建者，或群主/群管理员（开关可关） |
| `giveaway.time` | `时区` | `[偏移]`（如 `+8`）<br>选项 `-c` 本频道 / `-d` 默认 | ≥ `authorityManage` 或群主/群管理员 |
| `giveaway.locale` | `语言` | `[语言]`<br>选项 `-c` 本频道 / `-d` 默认 | ≥ `authorityManage` 或群主/群管理员 |
| `giveaway.channel` | `频道id` | — | 任何人（查看当前频道 id） |
| `giveaway.help` | `抽奖帮助` | — | 任何人（输出指令一览） |
| `giveaway.debug.honor` | `抽奖接口诊断` | — | ≥ `authorityManage` |
| `giveaway.debug.member` | `抽奖成员诊断` | `[用户]` | ≥ `authorityManage` |

> 直接发 `抽奖`（或 `抽奖帮助`）会输出一份**按语言分组的指令一览**：中文环境显示中文别名，英文 / 德文环境显示注册名，管理员额外看到诊断指令。

### 创建抽奖

```
> 创建抽奖
< 请复制下面这份模板，把每一项填好后发回给我（不需要的项留空即可）：
< 奖品：
< 开奖时间：
< 加入口令：
< 标题：
< 描述：
< 参与条件：等级≥40 活跃≥1 标识=群聊炽焰,龙王
< 说明一：奖品格式为「名称*数量」，多个奖品用逗号或空格分隔；开奖时间格式为「年-月-日-时-分」，留空表示不自动开奖。
< 说明二：「参与条件」一行可以不改（沿用控制台配置）、删空（本抽奖不做限制），或照「等级≥40 活跃≥1 连续≥7 标识=群聊炽焰,龙王」改写（不需要的项删掉即可）；多个标识的判定口径与「龙王」口径由控制台统一配置。
> 奖品：显卡*1，鼠标*2
> 开奖时间：09-15-20-00
> 加入口令：参加
> 参与条件：等级≥60 标识=龙王          ← 这一个抽奖单独提高门槛
< 创建抽奖成功，编号为 5645；加入口令：参加
```

熟手可以跳过模板，直接带参数创建：

```
抽奖 add 显卡*1 09-15-20-00 参加
抽奖 add -t 双十一抽奖 -d 满 40 级可参加 -r 显卡*1 n 参加
```

规则：

- **按标签取值**（`奖品：` / `开奖时间：` / `加入口令：` / `标题：` / `描述：` / `参与条件：`），顺序无关、半角全角冒号都认、中英德标签都能识别；整段复制粘贴也没问题（模板里的说明行会被忽略）
- **只有奖品必填**；缺奖品、开奖时间格式不对、回复 `q` / `取消`、或不回复 → **直接取消创建**（不追问），重新发送 `创建抽奖` 即可
- **留空按默认处理**：开奖时间留空 = 不自动开奖，口令留空 = 不使用加入口令（此时只能用 `加入抽奖 <编号>` 参与），标题 / 描述留空 = 用默认值
- 口令不为空时，成功提示会带上口令，方便创建者直接转发
- 奖品格式 `名称*数量`（数量可省略，默认 1）；多个奖品可用**逗号 / 顿号 / 空格**分隔，旧的竖线 `|` 仍兼容；奖品名里不要含空格或逗号
- 模板里填的值优先于 `-t` / `-d`；`-r` 允许同一个中奖人被重复抽中
- **参与条件**一行的三种改法：不改 = 沿用控制台配置（与全局等价时不落库）；删空 = 这个抽奖不做任何限制；改写 = 只覆盖写了的项（如 `等级≥60 标识=龙王`）。文本表达不了的口径（多标识判定、龙王口径）只在控制台配置、对所有抽奖动态生效

### 参与与查询

- **关键词加入**：直接在群里发送抽奖的加入口令（消息内容需与口令完全一致）
- `加入抽奖 <编号>` / `退出抽奖 <编号>`：指令式参与与退出
- `抽奖列表 [平台] [频道id]`：列出本频道的抽奖；带上平台与频道 id 可跨频道查询（频道 id 用 `频道id` 查看）
- `抽奖详情 <编号>`：标题、截止时间、描述、**当前生效的参与条件**、奖品列表与中奖名单
- `抽奖成员 <编号>`：参与名单

### 开奖与删除

- `开奖 [编号]`：不填编号时会列出**你创建的、尚未开奖的**抽奖，回复编号即可开奖
- 到点自动开奖：创建时填了开奖时间的抽奖会自动开奖，并把结果广播到抽奖所在频道
- `删除抽奖 <编号>`：删除抽奖（同时清理参与名单与已排定的开奖提醒）
- 开奖后记录按 `cacheHours` 保留，到期自动清理

### 开奖提醒

提醒完全由**控制台配置**驱动，群里不再有创建 / 启停提醒器的指令：

1. 在控制台把「开奖提醒」里的 `beforeEnd` 配成若干个时间点，例如 `0-0-0-1-0`（开奖前 1 小时）与 `0-0-0-0-10`（开奖前 10 分钟）
2. 之后**新建的**抽奖只要填了开奖时间，就会按这些时间点自动在群里播报：
   `编号为 XXXX 的抽奖还有 1 小时就要结束啦~`（倒计时按频道语言本地化）
3. 提醒任务随抽奖生命周期自动清理：手动 / 自动**开奖后不再提醒**，抽奖被**删除**或记录**过期清理**时一并取消

默认阶梯（跟着插件走，控制台里可改）：

| 偏移 | 含义 | 1 小时场次 | 5 小时场次 | 1 天场次 | 7 天场次 |
| --- | --- | --- | --- | --- | --- |
| `0-0-0-0-10` | 开奖前 10 分钟 | ✅ | ✅ | ✅ | ✅ |
| `0-0-0-1-0` | 开奖前 1 小时 | — | ✅ | ✅ | ✅ |
| `0-0-0-5-0` | 开奖前 5 小时 | — | — | ✅ | ✅ |
| `0-0-1-0-0` | 开奖前 1 天 | — | — | — | ✅ |
| `0-0-3-0-0` | 开奖前 3 天 | — | — | — | ✅ |

关键在于**偏移是「开奖前多久」，与抽奖本身多长无关**：已经过去的偏移会被自动跳过，
所以短场次天然只会收到靠后的那几档（1 小时场次就只提醒「开奖前 10 分钟」）。
`0-0-7-0-0` 这种「开奖前 7 天」对 7 天场次等于创建时刻本身，会被跳过，没有意义、不必配。

注意：

- 只对**填了开奖时间**的抽奖生效；已经不存在的抽奖不会再播报
- 修改控制台配置后，新创建的抽奖立即生效；已经在跑的抽奖会在机器人下次启动（`ready`）时按新配置重建提醒
- 嫌吵就删掉几行：例如只留 `0-0-0-1-0` + `0-0-0-0-10`（长场次只在收尾提醒两次）
- 提醒发到抽奖所在的**全部频道**（跨频道抽奖时每个频道都会收到）

### 设置与帮助

- `时区 [偏移]`：查看 / 修改时区，`-c` 只改本频道、`-d` 改默认值（影响开奖时间与提醒的本地时间显示）
- `语言 [语言]`：查看 / 修改语言偏好，`-c` 只改本频道、`-d` 改默认值
- `频道id`：显示当前频道 id（跨频道查询抽奖或排查绑定时用）
- `抽奖帮助` / 直接发 `抽奖`：输出指令一览

### 管理员诊断

两条指令都会把**原始返回**写进插件日志，便于线上排查：

- `抽奖接口诊断`：逐个尝试群成员信息、荣誉接口（OneBot 与 QQ 网页接口），打印取数结果与鉴权方式
- `抽奖成员诊断 [用户]`：打印指定成员的群聊等级 / 最后发言时间等原始字段

## 配置

在 Koishi 控制台的插件配置页可视化编辑，分四组：

| 分组 | 字段 | 说明 |
| --- | --- | --- |
| `basic` | `cacheHours` | 开奖后抽奖记录的保留时长（小时），默认 `72` |
| | `defaultTimeOffset` | 未设置时区的用户默认使用的时区偏移，默认 `+8` |
| `permission` | `authorityCreate` | 创建抽奖所需的最低权限等级，默认 `1` |
| | `authorityManage` | 管理**他人**抽奖（删除 / 手动开奖）所需的最低权限等级，默认 `3` |
| | `allowGuildAdminDelete` | 允许群主与群管理员删除本群抽奖，默认开启 |
| | `allowGuildAdminEnd` | 允许群主与群管理员对本群抽奖手动开奖，默认开启 |
| `join` | `minGroupLevel` | 参与抽奖所需的最低**群聊等级**（1~100），默认 `0`（不限制） |
| | `minActiveDays` | 要求最近 N 天内在本群发过言，默认 `0`（不限制） |
| | `minContinuousDays` | 要求**最长连续发言天数**不低于 N，默认 `0`（不限制） |
| | `requiredHonors` | 要求持有的 QQ 群**互动标识**（群聊之火 / 群聊炽焰 / 龙王），默认不限制 |
| | `honorMode` | 勾选多个标识时「满足任意一个」还是「必须全部满足」，默认任意一个（仅控制台配置） |
| | `dragonScope` | 「龙王」的判定口径：昨日活跃榜（默认）/ 仅当前龙王（仅控制台配置） |
| | `onFetchError` | 取不到成员 / 荣誉数据时放行还是拒绝，默认放行 |
| | `cacheMinutes` | 群荣誉数据的缓存时长（分钟），默认 `5` |
| `render` | `style` | 图片卡片风格：`default`（Koishi 品牌蓝紫渐变，默认）/ `anime`（二次元：樱花粉 + 薰衣草紫、圆角描边、表情与星光）/ `gothic`（哥特：暗夜黑 + 血红 + 古金、衬线字体与纹章装饰）/ `avemujica`（Ave Mujica：暗紫黑 + 玫红 + 哥特金、假面舞会气质） |
| | `banner` | 卡片顶部**头图**（可选）：http(s) / `data:` / `file:` URL 或本机绝对路径（自动转 file://），留空不显示 |
| | `create` | 创建成功后把抽奖内容渲染成图片，默认开启 |
| | `list` | `抽奖列表` 用图片渲染（需要 `puppeteer` 服务），默认开启 |
| | `result` | 开奖结果用图片渲染（需要 `puppeteer` 服务），默认开启 |
| | `avatar` | 开奖结果图片里显示中奖者的**头像与昵称**，默认开启 |
| `remind` | `beforeEnd` | **定时开奖前的提醒时间点**，可填多行（每行一次提醒）。格式 `年-月-日-时-分`（未用到的位填 `0`）：`0-0-0-1-0` = 开奖前 1 小时、`0-0-0-0-30` = 开奖前 30 分钟。默认阶梯：**开奖前 10 分钟 / 1 小时 / 5 小时 / 1 天 / 3 天**，即 `0-0-0-0-10`、`0-0-0-1-0`、`0-0-0-5-0`、`0-0-1-0-0`、`0-0-3-0-0`；只对填了开奖时间的抽奖生效，清空表示不提醒；开奖 / 删除后自动取消 |

### 图片渲染（可选）

装上并启用 `koishi-plugin-puppeteer` 后，下列两条消息会改用内置 HTML 模板渲染成图片：

| 消息 | 图片内容 | 渲染失败 / 未装 puppeteer 时 |
| --- | --- | --- |
| 创建成功（`创建抽奖`） | 标题、编号、开奖时间、描述、加入口令、奖品、参与条件（**图片代替文字**，不再重发成功文案） | 回退为原来的文字成功提示 |
| `抽奖列表` | 进行中 / 已结束状态、编号、标题、截止时间 | 回退为原来的文字列表 |
| 开奖广播 | 开奖编号、中奖者（**头像 + 昵称 + QQ 号**）、每人获得的奖品 | 回退为原来的完整文字消息 |

**交互矩阵**（是否出图只取决于「装了 puppeteer」+「对应开关」）：

| 依赖 / 开关 | 创建结果 | 抽奖列表 | 开奖结果 |
| --- | --- | --- | --- |
| 未装（或未启用）`puppeteer` | 文字 | 文字 | 文字（含 `@` 中奖者） |
| 装了 `puppeteer` 且 `render.*` 开启 | **图片** | **图片** | **文字（`@` 中奖者）+ 图片** |
| 装了 `puppeteer` 但对应开关关闭 | 文字 | 文字 | 文字 |

设计取舍：

- **开奖消息始终保留文字部分**：图片没法提醒到人，所以出图时仍会发一条带真实 `@中奖者` 的文字行，图片附在后面
- 渲染失败只打一条 `warn` 日志（含原因）并回退文字，**不会影响开奖 / 列表本身的逻辑**
- 图片里的标签随语言变化（简体中文 / English / Deutsch），抽奖标题等用户输入会做 HTML 转义，避免破坏排版
- 中奖者头像：优先用 OneBot 用户资料里的 `avatar`，取不到就按 QQ 号拼 qlogo 地址；
  昵称取不到时退化为只显示 QQ 号，头像加载失败时显示昵称首字（都不会出现破图）
- **四种风格**（`render.style`）：`default` 走 Koishi 品牌蓝紫渐变；`anime` 走樱花粉 / 薰衣草紫渐变、圆润描边、💗/🤍 状态表情、🎁 奖品与 ✨🌸 点缀；`gothic` 走暗夜黑 + 血红 + 古金、衬线字体、金色细描边、❖/✦ 纹章与罗马数字名次；`avemujica` 走暗紫黑 + 玫红 + 哥特金、🎭/🌹 点缀与「AVE MUJICA」字样（罗马数字名次）
- **头图**（`render.banner`）：可给卡片顶部加一张横幅图（任意 http(s) / `data:` / 本机绝对路径），四种风格通用；
  插件**不内置任何第三方美术素材**，请自行提供图片（官方立绘等请注意版权）
- 卡片结构：顶栏为 eyebrow + 标题 + 信息胶囊，正文用状态胶囊、等宽编号、奖品胶囊与分区小标题，
  开奖结果给中奖者加名次奖牌（🥇🥈🥉）、头像圆环与等宽 QQ 号，页脚是插件名（两种风格共用同一套排版，只换主题）
- 想要纯文字：把 `render.create` / `render.list` / `render.result` 关掉即可

### 参与条件

参与条件在**加入口令**与 `加入抽奖` 两条路径上都会检查，任一不满足即拒绝，并回带「你当前多少级 / 需要多少级」这类具体原因。

| 条件 | 数据来源 | 字段 | 备注 |
| --- | --- | --- | --- |
| 群聊等级 | OneBot `get_group_member_info` | `level` | NapCat 取 QQ NT 的 `memberRealLevel`，即群聊等级（1~100） |
| 最近发言 | OneBot `get_group_member_info` | `last_sent_time` | 不依赖 QQ 网页接口，比互动标识稳定，建议作为兜底 |
| 最长连续发言天数 | QQ 网页接口（火 / 炽焰榜） | `day_count_max` | 与官方「群聊之火 7 天 / 群聊炽焰 30 天」同源，但门槛可自定义；QQ 榜单只收录连续 ≥7 天的人，门槛建议 ≥7 |
| 群聊之火（连续发言） | `/cgi-bin/qunapp/honor_continuous` | `continuous_type=2` | 返回带 `day_count`（连续天数） |
| 群聊炽焰（连续 30 天） | 同上 | `continuous_type=3` | 持有炽焰者不再出现在火列表，插件自动把炽焰视为满足 7 天 |
| 龙王（昨日最活跃） | `/cgi-bin/qunapp/honor_talkative` | `talkative_list` / `current_talkative` | 默认看昨日活跃榜；`dragonScope: current` 时必须是榜单第一名本人 |

**为什么荣誉不走 OneBot 标准接口**：NapCat 的 `get_group_honor_info` 依赖 `qun.qq.com/interactive/honorlist` 页面里的 `window.__INITIAL_STATE__`，而该页已改版为 Vite SPA（变量不复存在），于是它**静默返回空列表**（截至 v4.18.19 仍未修复）。因此本插件：先用 OneBot 接口（未来修复即可自动生效），取不到数据时自动改用 QQ 新版网页接口兜底 —— 后者通过 OneBot 的 `get_cookies` 取 `qun.qq.com` 登录态，并算出 CSRF 令牌 `bkn`（只带 Cookie 会返回 `100021 csrf error`），归一化成与 OneBot 相同的结构。

注意事项：

- 网页荣誉接口依赖登录 Cookie，比成员信息慢、也更容易失败，因此按「群 + 类型」缓存（`cacheMinutes`），且只请求配置里真正用到的类型
- 两条路径都取不到数据时按 `onFetchError` 处理；荣誉列表返回全空也会被当作「取不到数据」（真实群聊榜上至少会有人），避免误判成「你没有标识」
- 非 OneBot 平台（如 Discord）拿不到这些接口，会跳过参与条件检查
- 控制台里「互动标识」若留了一行空值，会以 `null` 存进配置：插件**按无效值忽略**，并在启动日志告警说明当前实际生效的标识（候选项都是 `required`，空行在控制台上会显示为空行，不会伪装成已选中的某个标识）

### 权限模型

权限完全沿用 Koishi 自身的等级体系（用户表的 `authority` 字段由 `@koishijs/core` 提供，用户首次被观察到时按应用配置 `autoAuthorize` 写入，默认 `1`）：

| 等级 | 含义 |
| --- | --- |
| `0` | 封禁 |
| `1` | 普通用户 |
| `3` | 管理员 |
| `4` | 超级管理员 |

用 `admin user.authorize <等级>` 指令（需要 `@koishijs/plugin-admin`）或控制台的用户页面调整等级 —— 本插件**不维护独立的管理员名单**。此外：

- **群主与群管理员**始终可以创建抽奖，并可在开关允许时管理本群的抽奖（通过 OneBot 事件的群成员角色判定）
- **抽奖的创建者**始终可以管理自己创建的抽奖

## 事件

插件通过 Koishi 事件总线向外暴露生命周期事件，便于其它插件联动（前缀 `giveaway/`）：

| 事件 | 触发时机 |
| --- | --- |
| `giveaway/roll-add` | 创建抽奖（参数：session、roll、奖品列表、可选的 per-roll 参与条件） |
| `giveaway/roll-end` | 开奖 |
| `giveaway/roll-expired` | 抽奖记录到期清理 |
| `giveaway/roll-join` / `giveaway/roll-quit` | 用户加入 / 退出抽奖 |
| `giveaway/roll-key-update` | 加入口令缓存需要刷新 |
| `giveaway/remind-broadcast` | 开奖提醒到点广播（参数：抽奖 id） |
| `giveaway/reminder-add` / `giveaway/reminder-delete`、`giveaway/remind-add` / `giveaway/remind-delete` | 旧版手动提醒器事件，仅内部兼容保留，已不再有指令触发 |

## 开发

```bash
npm install
npm run build         # tsc 生成 lib/*.d.ts + esbuild 打包 lib/index.js
npm run build:watch   # 监听源码重新打包
npm run clean
```

构建脚本 `scripts/build.mjs` 只依赖本地 devDependencies（esbuild + js-yaml）：语言包 `.yml` 由 js-yaml 解析后交给 esbuild 的 json loader，`koishi` 等运行时依赖保持 external。

本地接入 Koishi 应用时（例如以 `file:` 依赖引入），改完代码需要重新 `yarn install` 刷新依赖副本并重启应用才生效；纯配置值（等级阈值、开关等）可在控制台热改，只有字段结构变更才需要重启。
